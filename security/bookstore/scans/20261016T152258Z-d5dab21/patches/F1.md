# F1: Stored XSS: buyer-supplied rating comment rendered via innerHTML after bypassSecurityTrustHtml

**Status:** patch written -> `F1.patch`

**Verified by a panel of agents.** An independent verifier reviewed the change against the finding and stated the three claims below with confidence, and a second, fresh reviewer challenged the diff for an attack path it opens, or a route it leaves open to the finding's exploit. The patch was written only because the panel could vouch for it; nothing here was applied for you.

RatingListComponent.commentHtml marked the buyer's raw comment trusted with bypassSecurityTrustHtml before the [innerHTML] binding; the patch returns the plain string so Angular's built-in HTML sanitizer runs, and drops the now-unused DomSanitizer injection.

## Confidence

- **the change is highly targeted to this finding** -- CONFIDENT: the diff touches only rating-list.component.ts: the bypass call, the import and injection that existed only to serve it, and the related comment and return type; the other changes in HEAD are left alone
- **the change introduces no new security vulnerability** -- CONFIDENT: the change only re-enables Angular's default [innerHTML] sanitization at rating-list.component.html:19; nothing is loosened, no new sink or input is added, and the component is used only by routing and DI
- **beyond closing the finding, the change does not alter the code's behaviour or the inputs it accepts** -- CONFIDENT: review only: plain-text comments and safe formatting render the same through the same binding; only the injected-markup class the finding names (event handlers, script, javascript: URLs, inline style) is stripped

**No project test of the patched code was run.** The behaviour claim rests on review of the change and its callers, not on a test run.

**Tests run:** none possible: npm test -- --watch=false in web/ failed with 'ng: not found' (no web/node_modules in the workspace, and dependencies were not installed)
